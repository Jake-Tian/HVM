# Hierarchical Video Memory

Pipeline for building graph memory from videos and answering QA with graph + video reasoning.

## Quick Start

1. **Install dependencies**
  ```bash
   pip install -r requirements.txt
  ```
2. **Set API credentials**
  - Ensure the required OpenAI/HF credentials are available in your environment.
  - Text and multimodal model calls are centralized in `utils/llm_gpt.py` and `utils/mllm_gpt.py`. If your provider or calling convention differs from the OpenAI-compatible API used here, update those adapter files.
  - Embedding calls are centralized in `utils/embedding.py`. Update this file if you use a different embedding provider or model.
3. **Run the pipeline preflight**
  ```bash
  python tests/run_pipeline_preflight.py
  ```
  - A full benchmark run can be expensive, so run this lightweight preflight first to catch environment and API integration problems before starting the full run.
  - Checks required files, dependencies, storage, process/thread capacity, OpenCV/FFmpeg, Hugging Face downloads, embeddings, and text/multimodal model calls.
  - Uses temporary files and does not overwrite outputs under `data/`.
  - Makes one embedding request, one text-model request, and one multimodal
  model request.
4. **Run the full pipeline**
  ```bash
   bash run_video_pipeline.sh
  ```
  - Uses `video_list.txt` by default.
  - You can also pass specific video names:
    ```bash
    bash run_video_pipeline.sh bedroom_01 kitchen_09
    ```
  - Processes up to 4 videos in parallel by default. Pipeline stages for each
  video run sequentially within that video's worker.
  - Set `MAX_PARALLEL_JOBS` to control concurrency. Use 1 for a fully
  sequential run:
    ```bash
    MAX_PARALLEL_JOBS=1 bash run_video_pipeline.sh
    MAX_PARALLEL_JOBS=2 bash run_video_pipeline.sh bedroom_01 kitchen_09
    ```



## What `run_video_pipeline.sh` does

1. Download shared data via `preprocessing/download_hf_folder.py`
2. Download each video via `preprocessing/download_hf_videos.py`
3. Build graph memory via `process_full_video.py`
4. Run QA reasoning via `reason.py`
5. Clean up downloaded MP4s and extracted frames



## Outputs

Per successfully processed video:

- `data/graphs/<video>.pkl` (graph memory)
- `data/memorization/<video>.json` (episodic memory + memory token summary)
- `data/reasoning/<video>.json` (QA reasoning results)



## Data Structure

Expected layout in `data/` (some folders are created/populated during pipeline runtime):

```text
data/
├── frames/
│   └── <video>/
│       └── <clip_id>/
│           └── *.jpg
├── videos/
│   └── <video>.mp4
├── subtitles/
│   └── robot/
│       └── <video>.srt
├── graphs/
│   ├── <video>.pkl
│   └── <video>_preabstraction.pkl
├── memorization/
│   └── <video>.json
├── reasoning/
│   └── <video>.json
├── ablation/
│   ├── graphs_abs/
│   │   └── <threshold>/<video>.pkl
│   └── reasoning_abs/
│       └── <threshold>/<video>.json
├── logs/
│   └── *.log
├── episodic_memory/
│   └── episodic_memory.json
├── reason_summaries/
│   └── reason_summary.json
├── analysis/
│   └── memorization_tokens.json
└── robot.json
```

Notes:

- `frames/`, `videos/`, and threshold graph files under `ablation/graphs_abs/` are temporary runtime artifacts cleaned up by `run_video_pipeline.sh`.
- Main graphs, pre-abstraction checkpoints, memorization results, reasoning results, threshold reasoning results, and logs are persistent outputs.
- `episodic_memory/`, `reason_summaries/`, and `analysis/` are generated by `scripts/data/reorganize_outputs.py`.



## Combine pipeline outputs

After the pipeline finishes, combine the per-video results and threshold abstraction results:

```bash
python scripts/data/reorganize_outputs.py
```

The script reads `data/memorization/`, `data/reasoning/`, and the three threshold reasoning directories under `data/ablation/reasoning_abs/`. It writes:

- `data/episodic_memory/episodic_memory.json`
- `data/reason_summaries/reason_summary.json`
- `data/analysis/memorization_tokens.json`

Threshold results are stored under each question's `threshold_abstraction` field in the combined reasoning summary. The script also prints baseline and threshold coverage counts so incomplete runs are visible.

## Project Structure

Core pipeline:

- `process_full_video.py` - build memory graph from frames
- `reason.py` - run the default five-tool reasoning agent
- `run_video_pipeline.sh` - end-to-end pipeline runner
- `preprocessing/` - dataset/video download and preprocessing
- `classes/` - graph, node, edge, conversation, and structured-output models
- `reasoning/` - default five-tool agent, prompts, runtime, and tools
- `utils/` - shared prompts, search, model adapters, token accounting, and helpers
- `configs/` - abstraction configurations used by the main and ablation pipelines

Alternative reasoning implementations:

- `reasoning_variants/` - fixed-pipeline and three-route backups retained for comparison and reproducibility

Experiment entrypoints:

- `abstraction_ablation.py` - rebuild threshold abstraction from a pre-abstraction checkpoint
- `noise_injection.py` - construct graphs for the noise-injection experiment
- `scripts/ablation/` - threshold and noise experiment runners

Supporting code:

- `scripts/data/` - combine per-video pipeline outputs
- `scripts/reasoning/` - reasoning experiment runners
- `scripts/graph/` - graph rebuild utilities
- `scripts/analysis/` and top-level `scripts/*.py` - result analysis, aggregation, evaluation, reporting, and graph inspection
- `tests/` - offline unit tests and the optional online pipeline preflight
- `docs/` - architecture notes and experiment analysis
